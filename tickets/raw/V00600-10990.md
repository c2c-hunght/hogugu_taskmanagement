## Description (Jira raw)

### Description

#### Background

Previously, we requested that customers who are **blocked by Operations from the Admin Dashboard** should no longer be able to use the pre-request chat.

### For below Case Details

* **Customer ID:** 056009584639619
* **Customer Name:** zyo
* **Chat ID:** 063718994108187_056009584639619
* **Block Date/Time:** August 16, around 10:00

The customer had a violation flag and could not voluntarily withdraw their account. Therefore, the customer contacted Operations to request account deletion, and Operations blocked the account at around 10:00 on August 16.

Before the account was blocked, at around 8:00, the customer had sent a message to the therapist through the pre-request chat.

However, when the therapist attempted to reply after the customer had already withdrawn/been blocked, the therapist could no longer send a message.

The therapist saw the following message:

> 「現在セラピストはチャットをOFFにしています。」

The therapist had **not turned off the pre-request chat**, so this caused confusion.

### UI Improvement Request

When the customer has withdrawn or has been blocked, displaying:

> 「現在セラピストはチャットをOFFにしています。」

is misleading because the therapist's chat setting is actually ON.

The therapist contacted Operations because they believed that their own chat setting was incorrectly recognized as OFF.

Therefore, we would like to change the message to one that accurately represents the actual state.

For example:

> 「お客様が退会されたため、チャットを利用できません」

Alternatively, a more general message such as:

> 「このチャットは利用できません」

would also be acceptable.

The main requirement is that **the displayed message should be consistent with the actual reason why the chat cannot be used**, rather than indicating that the therapist has disabled the chat.
