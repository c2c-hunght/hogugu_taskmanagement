# V00600-8741 [Hogugu][TS][Customer] AI Auto-Reply Sent (Violated Word ) Despite No Customer Message in Reservation Chat

**Source:** Reported via Technical Support ticket TS2-1478

## Issue

In the reservation chat, the violation warning `規約に沿わない恐れがあるワードを検知しました。` was sent even though no customer message is shown in the chat.

* **Reservation ID:** 195450817049180
* **Affected message:** 2025/12/17 18:45 (JST)

## Investigation result

* **Web (web-booking):** mark-suspicious is called before the Firestore save and without waiting for it (BookingChatModal `onSendingMessage`). If `batch.commit` fails, the warning is still sent.
* **iOS (customer-ios):** `save()` and `markSuspiciousChat` are fired at the same time (HOChatViewController `inputBar didPressSendButtonWith`). Save errors are ignored, and if `currentChatReference` is nil nothing is saved but the warning is still sent.
* **Flutter (customer-android):** the check runs only after `await set()` succeeds, so this is OK.

## Request

* **Web / iOS:** call mark-suspicious only after the Firestore save succeeds, the same way Flutter does. If the save fails, do not call mark-suspicious.

## Acceptance criteria

* Message with a prohibited word, save succeeds → message is shown and the violation warning is sent (no change from now).
* Message with a prohibited word, save fails (e.g. offline / Firestore error) → no violation warning is sent.
* Applies to both booking chat and direct chat room on Web and iOS.
