# V00600-11312 [Hogugu][Therapist][NOW] Show nearest station for NOW booking | NOW予約に最寄り駅を表示

## Background

* In the Therapist App **NOW booking list**, the location is shown only as **prefecture + city** (e.g. 東京都, 港区). Therapists cannot picture where the customer is without opening each booking.
* The address is shown in the new NOW request popup and the booking detail, but a street address is hard to picture quickly.
* We want to show the **nearest station(s)** to the customer's address, in the same way apartment rental websites (SUUMO, HOME'S, etc.) show access information, so therapists can picture the location right away.

## Current Behavior

| Screen | Location shown |
| --- | --- |
| Therapist App — NOW booking list | Prefecture + city |
| Therapist App — new NOW request popup | Address |
| Therapist App — NOW booking detail | Address |
| Dashboard — booking detail | Address |

No station information is shown today.

## Requirements

### 1. Where to display (NOW bookings only)

| # | Screen | Display |
| --- | --- | --- |
| #100 | Therapist App — NOW booking list | Full station list under prefecture + city |
| #101 | Therapist App — NOW booking detail | Full station list under the address |
| #102 | Therapist App — new NOW request popup | Full station list in a new row `最寄り駅` directly under `住所` |
| #103 | Dashboard — booking detail | Full station list under `住所` |

* "Full station list" = up to 3 stations (or the fallback in section 3), the same on every screen.
* Standard bookings are unchanged.
* When the booking is **done / canceled**:
    * Therapist App: station information is **hidden** (same as the address).
    * Dashboard: station information is **shown** (all statuses).

### 2. Display format

Rental-listing style, station name + walking time:

```
最寄り駅
・「目黒」駅 徒歩7分
・「白金台」駅 徒歩10分
・「白金高輪」駅 徒歩12分
```

* Up to **3 stations**, sorted by walking time (shortest first).
* Walking time = **actual walking route time** from the customer's address, rounded up to the minute.
* Train line names are not shown. The same station is shown only once.

### 3. When no station is close

Threshold: **20 min walk**.

| Case | Display |
| --- | --- |
| At least 1 station within 20 min walk | Stations within 20 min (max 3) |
| No station within 20 min, **a bus route to a station** exists | Up to 3 stations by bus: station → bus ride time → bus stop → walking time to the bus stop (see example below) |
| No station within 20 min and no bus route | Nearest station with its actual walking time, e.g. `・「〇〇」駅 徒歩35分` |
| Station cannot be determined (address not found, Google Maps error) | Station section hidden |

Example (no station within 20 min, bus available):

```
最寄り駅
・「目黒」駅 バス10分「白金台五丁目」停 徒歩3分
・「白金高輪」駅 バス12分「三光坂下」停 徒歩2分
・「広尾」駅 バス15分「広尾橋」停 徒歩5分
```

* The bus route is the Google Maps public-transport route from the customer's address to the station: walk to the bus stop, then bus to the station.
* Only routes with **one bus and no transfer** are shown.
* Up to **3 stations by bus**, sorted by total time (walk to bus stop + bus ride), shortest first.
* Bus times are based on:
    * the **booking time**, for bookings with a set time;
    * the **current time**, for "book right now" (今すぐ予約) requests.
* If no bus runs at that time, the bus route is not shown and the nearest station with its actual walking time is shown instead.

### 4. Rules

* Data source: **Google Maps**.
* The customer does not enter anything new. The station is determined from the address of the NOW booking.
* The station information is fixed when the booking is created and does not change afterwards.
* The station must already be shown in the popup when the NOW request arrives.
* Showing the station must not delay the NOW request notification by more than **3 seconds**. If the station is not ready in time, the notification is sent on time without it; the station row is then not shown in that popup.
* Failing to determine the station must never block creating the NOW booking, sending the NOW request to therapists, or accepting/declining it.

## Scope

* BE, Therapist iOS, Therapist Android, Dashboard
* **Out of scope:** standard bookings, push notification text, Customer apps, Web

## Acceptance Criteria

* Therapist App NOW booking list, NOW booking detail, new NOW request popup and Dashboard booking detail all show up to 3 stations within 20 min walk, sorted by walking time.
* In the popup, the stations are shown in `最寄り駅` under `住所`.
* Walking minutes are based on the actual walking route.
* No station within 20 min but one-bus routes (no transfer) exist → up to 3 stations by bus, sorted by total time, each as `「station」駅 バスX分「bus stop」停 徒歩Y分`.
* Bus times use the booking time (set-time booking) or the current time (今すぐ予約). If no bus runs at that time → the nearest station with its actual walking time is shown.
* No station within 20 min and no bus route → the nearest station with its actual walking time is shown.
* Station cannot be determined → station section hidden; the booking can be viewed, accepted and declined normally.
* The NOW request notification is not delayed by more than 3 seconds; if the station is not ready by then, the notification is sent without it.
* Done / canceled NOW booking: no station in the Therapist App; station still shown in the Dashboard.
* Standard bookings are unchanged.
* Verified on Therapist iOS, Therapist Android and Dashboard.

### Implementation hints for Dev (not part of the spec)
* Calculate at NOW booking creation, before `nowBooking.created` listeners send the first push (`start/events.js:143-150`, `Booking.notifyTherapistsWhenNowBookingComing`). The popup fetches booking detail on push arrival (iOS `HONowBookingRequestsPopupViewModel.swift:41-72`, Android `app_builder_notification.dart:313-328`).
* Reuse the account-api Google proxy: `GoogleProxyService.geocode` + `placeNearby` (Redis-cached, V00600-10609, commit 80208ade). No walking-route API exists yet → new Routes / Distance Matrix (walking) call.

* Retry: reminder pushes (`remindTherapistsAboutPendingNowBooking`) refetch, so a late result appears in later popups.
* Open for Dev: save geocoded coordinates on the booking for future use?
