# V00600-8630 [Hogugu][Dashboard][Customer][Therapist] When the operation (admin) cancels booking, send the cancel reason to the user. |機能追加依頼_運営キャンセルした場合にユーザーに理由を添えて送信したい

## Background
* When Ops cancels a booking from the Dashboard, a "cancelled by Operations" notification is sent, but **neither the therapist nor the customer can see the reason**.
* Today Ops sends the reason manually: to the therapist via **LINE**, to the customer via **email**. Ops wants to do this within the system.
* Volume: about **15 operation cancellations per month**.
* Source: TS2-1250 (2025/07/14).

## Current Behavior
* Admin cancel sends a push and an in-app notification to the therapist and the customer with a fixed text, without a reason:
```
{日時}〜の予約は運営によりキャンセルされました。
```
* The Dashboard cancel form has an optional 「キャンセル理由」 memo (max 500 characters). It is internal only and is not sent to users.

## Requirements
### 1. Dashboard: new reason fields
* Add **2 new optional fields** to the admin cancel form (the existing internal memo stays as it is, not sent to users):

  | Field | Rule |
  | --- | --- |
  | お客様へのキャンセル理由 | Optional, max 500 characters. Sent to the customer. |
  | セラピストへのキャンセル理由 | Optional, max 500 characters. Sent to the therapist. |

* Show a short note under the fields: 「入力した内容はお客様／セラピストに通知されます」.

### 2. Notification (push + in-app)
* The reason is added to the **existing admin-cancel push and in-app notification**, separately for the customer and the therapist:
```
{日時}〜の予約は運営によりキャンセルされました。
【理由】{理由}
```
* If a field is empty, that user gets the **current text unchanged**.
* Japanese only.
* Applies to all admin cancels: **normal, with cancellation fee (キャンセル料あり), and NOW** bookings.
  * Admin cancel with a cancellation fee: the customer and the therapist receive the admin-cancel notification as above (with the reason if entered).

### 3. Customer app: booking detail
* The booking detail of an admin-cancelled booking shows the **reason for the customer**:
```
【キャンセル理由】{理由}
```
* Not shown if the reason is empty.

## Scope
* Dashboard (cancel form), BE (notification)
* Notification recipients: Customer app / NOW / Web (incl. LINE Front and INBOUND), Therapist app
* Booking detail display: Customer iOS / Android, NOW, Web

## Acceptance Criteria
* Ops cancels with reasons → the customer and the therapist each receive push + in-app notification with their own reason.
* Ops cancels without reasons → the current text, unchanged.
* Only one field filled → only that user gets the reason; the other gets the current text.
* Admin cancel with a cancellation fee and NOW admin cancel behave the same.
* The customer sees the reason on the booking detail of the cancelled booking; nothing is shown if empty.
* The internal memo is never sent to users.

## Out of scope
* Preset reason templates
* Email / chat message
* EN text
* Showing the reason on the therapist app booking detail
