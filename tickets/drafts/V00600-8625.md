# V00600-8625 [Hogugu][Dashboard] Add Export Function for "Tentative / Confirmed Bookings" List in Dashboard

## Background

* The partner wants to **extract therapists who received their first booking request after registering on HOGUGU**, in order to do individual follow-ups.
* Looker updates only once a day. The partner needs an **export on the Dashboard** to check booking data in **real time**.
* Source: TS2-1411 「管理画面にて【仮予約/予約完了】一覧のエクスポート機能追加のお願い」.
* Partner's desired date: **2026/01**. [Q] Please agree a new date with the partner via TS2-1411 (the partner was told the timing would be discussed separately).

## Current Behavior

* Booking Management lists have only the 「キャンセル理由をエクスポートする」 export; the 仮予約/予約完了 tab has no booking export.
* The 仮予約/予約完了 tab shows matched bookings only. A therapist's first *request* (incl. declined / auto-cancelled) is in other tabs.
* The therapist CSV export already has 初報酬日 (first reward date), calculated in real time.

## Requirements

### 1. Export
* Add an **export function** to the 「仮予約/予約完了」 (Tentative / Confirmed Bookings) list under **[Booking Management]**.
* [Q] The partner's purpose (therapists' **first booking request**) does not match a booking export of the 仮予約/予約完了 tab. Which output is needed? (a) CSV of the 仮予約/予約完了 tab, (b) therapist-level "first request date" / "first confirmed booking date", (c) both. Suggest: **(b)** — add 「初リクエスト日時」 (first request date/time) and 「初予約確定日時」 (first confirmed booking date/time) columns to the **existing therapist CSV** export (it already has 初報酬日 in real time). Matches the stated purpose at lower cost.
* [Q] If (a): which list(s)? Normal bookings / All bookings / NOW / LINE / Inbound all have a 仮予約/予約完了 tab.
* [Q] If (a): columns. Suggest: Booking ID, booking type, booking date/time, request date/time, confirmed date/time, status, therapist ID, therapist registration date, "first booking for this therapist" flag, area, customer ID.
* [Q] Exclude customer phone / email / address? Suggest: exclude (PII policy).
* [Q] Does the export follow the current tab filters (date range, keyword)? Maximum date range? Encoding: UTF-8 with BOM like the existing CSVs?
* [Q] Permissions: Admin only, or also Operator (own areas) and Agent (own therapists)? Suggest: same role scoping as the existing cancellation-reason export.
* [Q] Button label and file name pattern (e.g. 「CSVエクスポート」).

## Scope

* Dashboard, BE
* [Q] Design: Suggest "no design needed" (one button next to the existing 「キャンセル理由をエクスポートする」, or no UI change if option (b)).

## Acceptance Criteria

* [Q] To be written after the option is decided. Suggest: export uses the current filters; row count equals the list count; column values match booking detail; role scoping works (Admin / Operator / Agent).

## Out of scope

* [Q] e.g. Looker changes; the option not chosen above.
