# [Hogugu][Dashboard][BE][Therapist] Manually grant bonus TP to therapists from the Dashboard | 管理画面から手動でセラピポイント付与

## Background
* Operations wants to run therapist campaigns, for example:
  * +10TP when the therapist completes ○ treatments in the campaign period
  * +10TP when the therapist completes ○ NOW treatments
* Operations checks who met the campaign conditions and grants the bonus TP manually.
* Today a manual grant needs a request to Dev (e.g. V00600-11707). Operations wants to do it in the Dashboard.

## Requirements
### 1. Grant bonus TP (Dashboard)
* On the therapist detail page → ポイント履歴 tab, add a **「ボーナスTP付与」** button.
* Input:

  | Field | Rule |
  | --- | --- |
  | 予約ID | Required. A booking of this therapist with status **施術完了**, completed **within the last 90 days**. |
  | 付与ポイント | Required. Whole number **1–100** TP per grant. |
  | 表示ラベル | Required. **Max 20 characters.** The text shown to the therapist in the point history, e.g. `11月キャンペーンボーナス`. |
  | メモ | Optional. Internal only, not shown to the therapist. |

* Confirmation popup before saving.
* After saving, the new row appears in the Dashboard point history with the label, memo and operator name.
* Errors (nothing granted):
  * Booking not found
  * Booking of another therapist
  * Booking not completed
  * Booking completed more than 90 days ago
* The same booking can receive more than one manual bonus.

### 2. Expiry and total
* The bonus TP expires **90 days after the treatment completion date of the linked booking** (same as normal TP).
* The row appears in the point history right after saving. The therapist's total TP and rank reflect it at the **next daily calculation**.

### 3. Therapist app
* Point history shows the bonus with the **表示ラベル** entered in the Dashboard.
* Old app versions show it as `ボーナス` (no crash, no blank label).
* Push notification to the therapist when the bonus is granted:
```
運営からボーナスポイントが付与されました。
```
* Tapping the push opens the point history screen.

### 4. Cancel / revoke
* Operators can revoke a manual bonus from its row in the Dashboard (「取消」 + confirmation popup).
* If the linked booking is later cancelled by an admin, the manual bonus is revoked together with the booking's other TP.
* A revoked bonus is shown as `付与取消` in the Dashboard and the therapist app.
* No push to the therapist on revoke.

## Scope
* Dashboard, BE
* Therapist iOS / Android (label display, push)

## Acceptance Criteria
* An operator can grant 1–100 TP with a label (max 20 characters) and optional memo, linked to one of the therapist's bookings completed within the last 90 days.
* 0, more than 100 TP, or a label over 20 characters → validation error.
* The row shows in the Dashboard (label, memo, operator) and in the therapist app (label). Old app versions show `ボーナス`.
* Invalid booking (not found, other therapist, not completed, completed > 90 days ago) → error, no TP.
* The same booking can be granted more than once.
* The therapist receives the push when the bonus is granted; tapping it opens the point history. No push on revoke.
* The bonus expires 90 days after the linked booking's completion date and appears in the expiring points; total TP / rank update at the next daily calculation.
* Operator revoke, or admin cancellation of the linked booking → bonus revoked, shown as `付与取消`.

## Out of scope
* Automatic campaign judgement (counting completed treatments). Operations checks the conditions manually.
* Bulk grant (CSV).

* **Old app = 「ボーナス」 → recommended implementation:** keep type **AWARD** / REVOKE_AWARD (old apps already label it 「ボーナス」 / 「付与取消」) and add a new `label` field. New app versions show `label` when present.
  * A brand-new type cannot fall back to 「ボーナス」: old iOS shows "History point" / blank, old Android shows ''.
  * The BE cannot serve different types per version: iOS sends no `X-App-Version` (verified earlier this month).
  * Caveat: AWARD on a NOW booking shows 「ボーナス(フリー予約)」 on the Dashboard and Android (`messages.js:62-83`, `booking_point.dart`). Acceptable on old apps; new apps use the label.
* There is no admin API or screen to grant points today. The only manual change is the booking penalty (ADD_PENALTY / REMOVE_PENALTY), `servers/hogugu-booking-api/app/Repos/BookingRepo.js:2565-2595`.
* The Dashboard point history tab is read-only: `apps/hogugu-dashboard-app/app/components/TherapistPointHistoryTab/index.js:22-39`. API `GET therapist/:id/point-history` is at `hogugu-account-api/start/routes.js:116-119`.
* Point records are stored in Mongo `point_histories` `{type, point, timestamp, therapistId, customerId, bookingId, author}` (`hogugu-account-api/app/Listeners/PointHistory.js:17-100`). There is a single writer: the MQ listener `storePointHistory` (`start/rabbitmq.js:234-236`). New fields `label` and `memo` are needed.
* Expiry = a rolling 90-day window on `timestamp` (`config/constants.js:82`), computed by the daily job (`Listeners/Therapist.js:343-391`).
  * → `timestamp` = the linked booking's completion time gives "90 days from completion".
  * The job only processes therapists with `lastBookingTime` ≤ 91 days; this is fine because the booking is ≤ 90 days old.
* Admin cancel → REVOKE lookup by `bookingId` includes AWARD (`PointHistory.js:48-90`) → manual AWARD rows are revoked automatically. Operator revoke of a single row is new.
* Labels: iOS `Enums+Ranking.swift:134-178` (AWARD/REVOKE_AWARD present); Android `booking_point.dart:28-35, 96-110`.
* Rough cost:
  * BE 3 d (API grant/revoke, label/memo, push)
  * Dashboard 2–3 d
  * iOS / Android 0.5–1 d each (show label)
  * QC 2 d
* The Dashboard "therapist-awards" feature (`AddAwardModal.js`) is about badges and frames, not points. Don't confuse the two.
