# V00600-10084 [Hogugu][Customer] Therapist recommendation list (replace new-therapist slider) | カスタマー向けレコメン機能

## Background

The customer app's search/home screen currently shows a **"new therapist" slider** — a generic list of newly-joined therapists that is the same for everyone and not tailored to the individual customer.

[Q] The slider is on the therapist **search result** screen, not home. Suggest: fix wording to "search result screen".

## Purpose

Show each customer therapists that are more relevant to them (instead of a generic new-therapist list), improving discovery and booking conversion, and letting us tune the recommendation logic quickly server-side.

[Q] Target KPI and baseline.

## Current Behavior

* The new-therapist slider shows newly-joined therapists, the same for every customer, and only therapists with available timeslots for the search conditions.

## Requirements

### 1. Personalized recommendation list

* Replace the **new-therapist slider** with a **personalized therapist recommendation list**, similar to Amazon's product recommendations.
* The list is generated **based on the customer's own data** and sent to that customer.
* The recommendation **calculation must be updatable from the server** — the algorithm / weighting can be changed and tuned server-side **without requiring a customer-app release**.

> **Recommendation calculation: not yet defined (waiting for definition).** The exact recommendation logic / algorithm is still to be decided and will be defined separately.

[Q] Recommendation calculation / algorithm (計算ロジック未定義). Suggest: reference Hung's draft `requirements/recommender-system.md` once approved.
[Q] Surface: Phase 1 = slider only (matches this ticket and design), or the whole "Recommend" list order (draft v0.1)? Suggest: Phase 1 = slider only; list-order personalization in a new ticket.

### 2. Points to confirm

[Q] **Input data:** which customer data feeds the recommendation? (e.g. booking history, favorites, viewed / searched therapists, area, menu / price preferences.)
[Q] **Relationship to existing "Recommend" sort:** there is already a rule-based "Recommend" ordering (approval rate → response time → reviews → availability …). Does this personalized list **replace** it, or sit alongside as a separate section?
[Q] **New / low-data customers:** fallback when the customer has little or no history (e.g. popular or nearby therapists)?
[Q] **New-therapist exposure:** removing the slider removes the only boost for new therapists. Suggest: include a cold-start boost for new therapists (draft FR-4). Partner OK to lose the slider?
[Q] **Availability filter:** should recommendations only include therapists with available timeslots (as the new-therapist slider does today)? Suggest: keep as a hard filter (draft FR-1).
[Q] **Presentation:** list size, ordering, and how often it refreshes.
[Q] **Data prerequisite:** event logging / baseline KPI (draft Phase 0) — where are Firebase events stored and queryable?
