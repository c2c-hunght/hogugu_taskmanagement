# V00600-10085 [Hogugu][Therapist][Dashboard] Therapist new account creation flow change | 機能改修依頼_セラピスト新規アカウント作成フロー変更

**Source:** Partner request via Technical Support ticket TS2-1381 (2025-09-29)

## Background
* Re-raising a previously discussed request. We want to change the therapist new-account creation flow.
* Purpose: therapists can try the app first and get a feel for how it works, so they can more easily picture working on it. They then go through the operations review and a registration orientation session.

## Current Behavior
| Current | New |
| --- | --- |
| Therapists cannot sign up in the Therapist app. Ops creates the account on the Dashboard; the therapist then logs in with the phone number and updates the profile. | Therapists register themselves in the Therapist app with their phone number. Ops can still create accounts on the Dashboard. |

## Requirements
### 1. Self-registration (Therapist app)
* Therapists can register on their own with their phone number.
* Registration fields:

  | Field | Rule |
  | --- | --- |
  | 氏名 (Full name) | Required |
  | ニックネーム (Nickname) | Required |
  | 生年月日 (Birthday) | Required |
  | 電話番号 (Phone number) | Required (login ID) |
  | メールアドレス (Email) | Required |
  | 本人確認書類 (ID document) | **Optional at registration** — can be skipped and submitted later (§3) |

* After registering, the therapist is logged in and can continue setting up the profile.
* Account creation by Ops on the Dashboard **stays as today**. Existing therapists are not affected.
* Phone number checks (already registered, deleted / banned therapist, OTP limits): **same as the current logic**.

### 2. Provisional registration (仮登録) and going live
* Right after registering, the account is **provisional (仮登録)** and is **not shown to customers** (search, schedule search, therapist list, etc.).
* While provisional, the therapist **can set up everything needed to work** (profile, menus, schedule, area, bank information, etc.), so they can start working as soon as Ops approves. Because they are not shown to customers, they cannot receive bookings.
* Ops approves or rejects the therapist on the Dashboard (§4). Every status change is done by Ops.
* Shown to customers only when **both**: Ops approved **and** profile completed.

  | Ops review | Profile | Shown to customers |
  | --- | --- | --- |
  | Not approved (仮登録 / rejected) | any | No |
  | Approved | Not completed | No |
  | Approved | Completed | **Yes** |

* Provisional accounts that are never completed stay as they are (no auto-delete).

### 3. ID verification (本人確認書類) in the app
* ID document: **front and back** images.
* Can be submitted at registration or later from the app.
* If Ops rejects it, the app shows the **rejection reason entered by Ops** on the Dashboard, and the therapist can resubmit.
* ID images are **deleted 15 days after approval**. Images of rejected therapists are kept (not auto-deleted).
* ID images can be viewed **only by admin** on the Dashboard.

### 3-1. Popup at app start (not verified)
* Every time the therapist **starts the app**, if the account is **not verified**, a popup is shown with a button that opens the ID submission page.

  | Review status | Popup |
  | --- | --- |
  | ID not submitted | **Shown** — 「本人確認書類を提出する」 |
  | Rejected | **Shown** — 「再提出する」 (with the reason) |
  | Submitted, under review (審査中) | Not shown |
  | Approved | Not shown |

* The popup can be closed. It shows again at the next app start while the condition remains.

### 4. Ops review on the Dashboard
* Therapist list: add a filter by review status (仮登録 / 審査中 / 承認済み / 否認).
* Therapist detail: view the ID images; **approve** or **reject** with a reason (shown to the therapist).
* No separate approval queue and no notification to Ops on new sign-ups. Ops uses the filter.
* The registration orientation session (登録説明会) is handled by Ops outside the system.

## Scope
* Therapist App (iOS / Android), Dashboard, BE
* Customer-side apps (Customer iOS / Android, NOW, Web): only hide provisional / not-approved therapists.

## Acceptance Criteria
* A new therapist can register in the Therapist app with full name, nickname, birthday, phone number and email; the ID document can be skipped.
* Phone number checks behave as today.
* Ops can still create therapists on the Dashboard; existing therapists are not affected.
* A provisional therapist can set up profile, menus, schedule, etc., but is not shown in any customer search / list.
* The therapist can submit the ID document (front + back) at registration or later.
* Ops can filter therapists by review status, view the ID images, and approve or reject with a reason.
* A rejected therapist sees the reason in the app and can resubmit.
* The therapist receives the approval / rejection push (§5).
* At app start, a not-verified therapist (ID not submitted / rejected) sees the popup every time; its button opens the ID submission page; closing it shows it again at the next start.
* ID images are viewable only by admin and are deleted 15 days after approval.
* Approved + profile completed → shown to customers; approved + profile not completed → not shown.
* The texts in §5 are shown in the right states.

## Out of scope
* Automatic eKYC (external vendor)
* Approval queue / notification to Ops on new sign-ups
* Orientation session management in the system
* Auto-delete of provisional accounts
