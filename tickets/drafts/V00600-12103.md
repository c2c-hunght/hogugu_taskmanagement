# [Hogugu][Customer][Therapist][Now][Web][LINE] Maintenance switch via Firebase Remote Config (with dev-device bypass)｜Firebase Remote Configによるメンテナンス切替

## Background
When our servers are down, the apps keep calling them and users hit errors or partial failures (e.g. phone number blocked). We need a **last-resort switch that does not depend on our servers**, so Ops/Dev can stop all app usage at once and show a clear maintenance message.

Firebase Remote Config runs on Google infrastructure, separate from ours, so it keeps working while our servers are down.

During maintenance the Dev team still needs to use the apps against the server (to verify the fix / release), so registered dev devices must be able to bypass the switch.

## Requirements

### 1. Server status switch (Firebase Remote Config)
* One switch in Firebase Remote Config with two values: **OK** (normal) / **NG** (maintenance).
* The switch can be set **per app** (Customer iOS, Customer Android, NOW, Therapist iOS, Therapist Android, Web booking, LINE front).
* The maintenance message is set in Remote Config together with the switch, so Ops can change it without a release.
* If the app cannot reach Firebase, it uses the last value it received. If it has never received a value, it treats the status as **OK** (the app must never be blocked by a Firebase/network problem).

### 2. App behavior when status = NG
* The app shows the maintenance popup:
  * At app start (before the first screen is shown)
  * When the app returns to the foreground
  * **While the app is open**, within a few seconds of Ops switching to NG (no restart needed)
* The popup **cannot be closed** and blocks all app operations.
* When the status returns to **OK**, the popup closes automatically and the app continues normally (no restart needed).
* The maintenance popup is shown **first**, before any other app-start popup (force update, ID-review popup V00600-10085, etc.).
* Popup text (**JP only**, all apps incl. EN language setting). Default text below; Ops can change it in Remote Config without a release:
```
タイトル：メンテナンス中
本文：現在、サーバーメンテナンスを実施しています。
しばらく時間をおいてから、再度お試しください。
```
* **Expected end time (optional):** Remote Config has an optional end-time field. If it is set, the popup shows it under the body text; if it is empty, the line is not shown.
```
終了予定：2026/11/13 15:00
```
* The existing maintenance screen stays as it is.

### 3. Dev-device bypass (whitelist)
* Ops/Dev keep a list of **device IDs (Firebase Installation ID)** in Remote Config.
* A device in the list **ignores status NG** and works normally.
* Debug / staging builds (Web / LINE front: staging environment) always ignore status NG.

### 4. Hidden "Device info" screen
So a dev can find the device ID of a production build:
* **Tap the app version label 7 times** → a "Device info" dialog shows the device ID and a **Copy** button.
* The same 7-tap gesture also works on the **maintenance popup title**, so the ID can be read even while the app is blocked.
* Version label location: Settings / About / Account screen of each app (where the version is shown today).
* Note: the device ID changes when the app is reinstalled or its data is cleared → the device must be registered again.

### 5. Web booking (booking.hogugu.com incl. INBOUND) and LINE LIFF booking pages
* Same switch, popup, text, end time and bypass rules as §1–§3, with these differences:
  * The popup is shown when a page is opened, and **while the page is open within about 1 minute** of switching to NG (and closes within about 1 minute of switching back to OK).
  * Bypass: device ID = the browser's Firebase Installation ID. It changes when the browser data is cleared or another browser is used (for LIFF: per LINE app on the device).
  * Device info: there is no version label on Web/LIFF → the device ID is shown only by **tapping the maintenance popup title 7 times**.
* Web: the existing Web maintenance page (shown for all requests during planned maintenance) **stays as it is** and is used for **planned** full maintenance. The new switch is used for **sudden** server-down.

### 6. LINE chat (AI concierge / bot)
* The LINE chat behavior while status = NG (bot replies, bypass for dev users, conversations in progress, FAQ / escalation) **should be defined** in the LINE front spec. Please define and share it.

## Scope
* Customer iOS / Android, NOW, Therapist iOS / Android
* Web booking (booking.hogugu.com incl. INBOUND)
* LINE front: LIFF booking pages (LINE chat: spec to be defined, §6)
* Firebase Remote Config setup (production + staging projects)
* No change to the main Hogugu servers (LINE front server changes only)

## Expected Behavior / Acceptance Criteria
* Status OK → all apps work as today.
* Status NG for one app → only that app shows the maintenance popup; other apps are not affected.
* Status NG while the app is open → popup appears without restarting the app.
* Status NG → OK while the popup is shown → popup closes without restarting the app.
* App start with no network to Firebase and no previous value → app works normally (status OK).
* Device in the bypass list → no popup while status = NG, all functions work.
* Debug / staging build → no popup while status = NG.
* 7 taps on the version label or on the maintenance popup title → device ID is shown and can be copied.
* Popup text matches the JP text in Remote Config (also when the app language is EN).
* End time set → shown in the popup; end time empty → no end-time line.
* Status NG + another app-start popup (e.g. force update) → only the maintenance popup is shown.
* Web / LIFF: status NG → popup on page open; NG while a page is open → popup within about 1 minute; back to OK → popup closes within about 1 minute.
* Web / LIFF: 7 taps on the popup title → device ID shown and can be copied; browser in the bypass list → no popup.

## Operation (Ops / Dev)
* The switch is changed **only on request from the manager**.
* Please share a short runbook: how to switch OK ⇄ NG, how to set the message / end time, how to add/remove a dev device.
* Please limit edit access to Remote Config in the Firebase console to the people in the runbook.

## Out of scope / Future consideration
* App versions released before this change do not support the switch.
* Automatic switching from server monitoring alerts (phase 2).
* Corporate site (hogugu.com / web-jp) and Dashboard.
