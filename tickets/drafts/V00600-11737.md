# [Hogugu][Customer][Therapist][BE] Auto-reply in pre-request chat when the therapist has not logged in for 48 hours | リクエスト前相談チャットへ自動応答追加

## Background
* In the pre-request chat (事前チャット), some therapists have not logged in for a long time. Customers send messages and get no reply.
* We want to tell the customer automatically that a reply may take time or may not come.

## Requirements
### 1. Trigger
* A customer sends a message in the pre-request chat, **and**
* the therapist's last login was **more than 48 hours ago** at that moment.
  * "Last login" = the same last-login time used for the therapist's 「最終ログイン」 status shown to customers. It is updated when the therapist opens the app.

### 2. Message
* An automatic message is posted in the chat right after the customer's message:
```
このセラピストは一定期間ログインが確認されていません。返信にお時間がかかる、または返信がない場合があります。
```
* Shown as a system message with the sender name `AI自動返信` (same as the existing automatic messages in chat).
* Japanese only.

### 3. Only once until the therapist replies
* The automatic message is sent **once**. If the customer keeps sending messages, it is not repeated.
* It can be sent again **only after the therapist has replied to the customer** in this chat.
* The therapist logging in again does **not** reset it.
* Example:

  | # | Event | Auto message |
  | --- | --- | --- |
  | 1 | Therapist inactive > 48 h → customer sends a message | **Sent** |
  | 2 | Customer sends more messages | Not sent |
  | 3 | Therapist logs in, does not reply, becomes inactive > 48 h again → customer sends a message | Not sent |
  | 4 | Therapist replies to the customer | (reset) |
  | 5 | Therapist inactive > 48 h → customer sends a message | **Sent** |

### 4. Therapist side
* The therapist also sees the automatic message in the chat.

## Scope
* BE
* Customer iOS / Android, Web (booking.hogugu.com incl. INBOUND), Therapist iOS / Android: no change expected (system messages are already displayed)
* NOW: not applicable (no pre-request chat)

## Acceptance Criteria
* Therapist last login > 48 h → customer sends a message → the automatic message appears once, sender `AI自動返信`.
* Customer sends more messages → no further automatic message.
* Therapist logs in but does not reply, then becomes inactive > 48 h again → customer message → no automatic message.
* Therapist replies → later inactive > 48 h → customer message → the automatic message appears again (once).
* Therapist last login ≤ 48 h → no automatic message.
* The message is displayed correctly on Customer iOS / Android / Web and Therapist iOS / Android.

## Out of scope
* Booking (request) chat — it already has its own automatic replies.
* Notifying the therapist by push / LINE / email to log in.

## Verification notes (local only — not pushed)
* `lastLogin` lives on Therapist (`servers/hogugu-account-api/app/Models/Therapist.js:143`). It is updated:
  * on login / token issue (`Common/Therapist/AuthenticationController.js:58, 93`)
  * on every `GET /me` (`Common/Therapist/MeController.js:91-100`, = app open / profile fetch)
* It is shown to customers via `Utils.getLastActiveStatus` (`servers/common/hugo-utils/src/index.js:96-115`).
* **Pre-request chat messages have no backend endpoint.** Clients write directly to Firestore `rooms/{therapistId_customerId}/messages` (web example `apps/hogugu-web-booking/src/models/chat/chatService.ts:115-136`).
  * → The trigger needs one of: a Firestore onCreate trigger (Cloud Function), a client call to a new BE endpoint after sending, or a check when the room is created (`POST /chat/rooms/:therapistId`, `hogugu-booking-api/start/routes.js:474-478`).
  * Room creation only = one check per room. That does not cover "therapist became inactive later" or the reset by therapist reply. Dev to choose the mechanism; this is the main cost driver (likely a Firestore onCreate trigger on `rooms/*/messages`).
* Reusable helper: `AutoReplyService.sendDirectChatSystemMessage(roomId, content, messageType)` (`hogugu-booking-api/app/Services/AutoReplyService.js:211-284`).
  * It writes to `rooms/{roomId}/messages`, updates `lastMessage`, and **increments unread for both users** → relevant to §4.
  * It is used today for the violation warning (`:829-861`).
  * The system user is `AI自動返信` (`:60-67`).
* Clients render system messages:
  * iOS `MockMessage.swift:216-236` + `HOAssistantMessageCollectionViewCell` (TEXT/LOCATION only)
  * Android `chat_message.dart:74-79`
  * Web `TherapistChatModal/index.tsx:572-579`, `ChatBubble/index.tsx:248-343`
  * → No client change for a TEXT system message.
* "Once until the therapist replies" needs a flag on the room (e.g. `inactiveNoticeSentAt`), cleared when the therapist sends a message in that room. Therapist messages are also written directly to Firestore → the clear also needs the trigger mechanism above.
* Therapist apps render system messages: Android `lib/screens/chat_flow/chat_thread/widgets/message_box.dart:61-68`, `left_message_item.dart:67`; iOS `HoguguTherapist/Model/Chat/MockMessage.swift:186-190, 237-241` (origin/develop).
* Rough cost:
  * BE 2–3 d (+1–2 d if a Firestore trigger / Cloud Function is new infra)
  * QC 1–2 d
  * Apps 0 d
