# V00600-11308 [Hogugu][Customer][Therapist][Now] Improve Onesignal PlayID handle

## Background

* Some devices' OneSignal ID (player ID) is not saved on the server.
* As a result, push notifications do not arrive on those devices.

## Requirements

### 1. Keep the latest OneSignal ID of every device on the server

Update the apps and the server so that the **latest OneSignal ID of each device is always saved on the server** for the logged-in user, including when:

* the app is installed and the user logs in / signs up for the first time
* the user is already logged in and opens the app
* the OneSignal ID of the device changes (e.g. reinstall, OS / SDK update)
* the OneSignal ID is not ready yet at login or app start
* sending the ID to the server fails (e.g. network error)

### 2. Old / wrong IDs

* When the user logs out, that device no longer receives the user's push notifications.
* When another user logs in on the same device, push notifications go only to the new user.
* IDs that are no longer valid must not stop push notifications from reaching the user's current device.

### 3. Detailed design before development

* Before starting development, please share a **detailed design** on this ticket (current problems found, solution per app and server, impact, test plan).
* Development starts after the design is reviewed and confirmed.

## Scope

* Customer iOS / Android, NOW, Therapist iOS / Android, BE

## Acceptance Criteria

* The detailed design is shared on this ticket and confirmed before development.
* In all cases listed in Requirement 1, the device's latest OneSignal ID is saved on the server and push notifications arrive on that device.
* After logout, the device no longer receives that user's push notifications.
* After switching accounts on the same device, only the new user's push notifications arrive.
* Verified on Customer iOS / Android, NOW, Therapist iOS / Android.

Original content: "fix bug". Investigation below was done on 2026-09-29 before Hung said no investigation is needed; kept only as background for reviewing Dev's design.

### Apps
| App | OneSignal SDK | When the ID is sent | ID change observer | Gap |
| --- | --- | --- | --- | --- |
| Customer iOS | 2.11.2 (legacy) | Login only | Saves locally, no send | Not sent if ID arrives late; never on launch; result ignored |
| Therapist iOS | 2.11.2 (legacy) | Login + every screen until success | Clears "uploaded" flag → re-send | Best behavior; flag not cleared on logout |
| Customer Android (Flutter) | 5.2.6 | Launch/login when flag false | Saves locally, no send | ID change never re-sent |
| NOW (Flutter) | 5.2.2 | Every main screen init + observer | Sends on change | Can send empty `""` |
| Therapist Android (Flutter) | 5.5.8 | App loading when flag false | Saves locally, no send | Flag set true even on error response; ID change never re-sent |

No app calls `OneSignal.login(externalId)` / `setExternalUserId`.

### Server (hogugu-notification-service)
* `POST mobile/{customer|therapist}/installation`, `now/mobile/customer/installation`; body `playerId`; collection `installations` `{playerId, userId, role, app, isBlocked}`, upsert by `{playerId, role}` (`InstallationRepo.js:23-56`).
* No device key → a changed ID is added and the old one is never removed; no cleanup of `invalid_player_ids` (200 response not inspected); pushes use `include_player_ids` only (`pushHelper.js:88-116`, `onesignal-node ^2.0.1`).
* Logout removes the row only on exact `{playerId, userId, role}` match (`InstallationRepo.js:104-115`) → stale ID stays linked.
* Moved row keeps previous user's `isBlocked`.
* No unique index on `{playerId, role}` found.
