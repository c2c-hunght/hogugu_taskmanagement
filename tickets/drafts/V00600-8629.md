# V00600-8629 [Hogugu][Dashboard] Booking management_Split the cancellation status by type|管理画面改修依頼_予約管理のキャンセルステータスのアイコンを種別ごとに分ける（アプリも揃えたい）

## Background
* On the Dashboard booking management screen, the **type of cancellation cannot be distinguished** on the list page.
* Source: TS2-1249 (partner request, 2025/07/14). The partner also wants the apps aligned.
* Dashboard and apps should be done **at the same time**.

## Current Behavior
* The Dashboard list shows 「セラピキャンセル」 only when a therapist cancels a **confirmed** booking, and 「キャンセル」 for all other cancel types.

## Requirements
### 1. Cancellation types and labels
Show the cancellation status as a **text badge with a colour per type** (no icon design needed):

| Label | Condition |
| --- | --- |
| お客様取消 | Customer cancels **before matching** (before a therapist accepts) |
| お客様キャンセル | Customer cancels **after matching** (after a therapist accepts / booking confirmed) |
| セラピキャンセル | Therapist **declines a request** |
| 自動キャンセル | System cancels automatically (expired: no response within the time limit, incl. the 24h no-response cancel) |
| マッチング不成立 | NOW booking cancelled because **no therapist matched** (shown separately from 自動キャンセル) |
| 確定予約キャンセル | Therapist cancels a **confirmed** booking |
| 運営キャンセル | Operator cancels |
| キャンセル | Fallback: old bookings with no / unknown reason (current label) |

* "Matching" = a therapist accepted the booking. Same rule for NOW bookings.
* **Meaning change:** 「セラピキャンセル」 now means "therapist declined a request". The current meaning (therapist cancelled a confirmed booking) becomes 「確定予約キャンセル」. Please announce this to Ops.

### 2. Where (Dashboard)
* The status cell of **all booking lists**: normal / All / NOW / LINE / Inbound.
* Cancellation-reason CSV: add a **cancel type** column with the same labels.

### 3. Apps
* **Customer iOS / Android, NOW, Web, Therapist iOS / Android** show the same labels as the Dashboard (§1) on the **booking list** and **booking detail**.
* Customers and therapists see the same wording as the Dashboard (e.g. 「運営キャンセル」, 「自動キャンセル」).

## Scope
* Dashboard (all booking lists, cancellation-reason CSV)
* BE (if needed to tell before / after matching and the NOW no-match case)
* Customer iOS / Android, NOW, Web, Therapist iOS / Android (booking list / detail)

## Acceptance Criteria
* For each type in §1, a booking cancelled that way shows the matching label in all 5 Dashboard lists.
* NOW "no match" shows 「マッチング不成立」, separately from 自動キャンセル.
* Old bookings without a reason show 「キャンセル」.
* The cancellation-reason CSV has a cancel type column with the same labels.
* Customer iOS / Android, NOW, Web and Therapist iOS / Android show the same labels on the booking list and booking detail.

## Out of scope
* Changes to cancellation logic or cancellation charges
* Sales summary
* A filter by cancel type
